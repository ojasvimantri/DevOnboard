# Onboarding Skill

You are performing a deep codebase analysis to generate a first-day onboarding guide.
Follow the three phases below in strict order. Do not skip phases.

---

## Phase 1 — Discovery (Read the project)

Read the following files in this priority order. Note what you find at each step.

### Step 1: Root-level files
Read every file that exists at the project root:
- `README.md` — project purpose, setup instructions, any existing docs
- `package.json` / `package-lock.json` — Node.js stack, scripts, dependencies
- `pyproject.toml` / `requirements.txt` / `setup.py` — Python stack
- `pom.xml` / `build.gradle` — Java/Kotlin stack
- `Cargo.toml` — Rust stack
- `go.mod` — Go stack
- `Makefile` — available dev commands
- `docker-compose.yml` / `Dockerfile` — containerisation
- `.env.example` / `.env.sample` — environment variables
- `CONTRIBUTING.md` / `CHANGELOG.md` — team conventions

### Step 2: CI/CD and configuration
- `.github/workflows/` — CI pipelines and deployment
- `.gitlab-ci.yml` / `Jenkinsfile` — alternative CI
- `vite.config.*` / `webpack.config.*` / `babel.config.*` — build tools
- `tsconfig.json` / `jsconfig.json` — TypeScript config
- `jest.config.*` / `vitest.config.*` — test config
- `eslint.config.*` / `.eslintrc.*` / `.prettierrc` — code quality

### Step 3: Directory structure
List and analyse the top 2 levels of the directory tree.
Identify the purpose of each top-level folder.
Then read the key source folders more deeply (typically `src/`, `app/`, `lib/`).

### Step 4: Entry points
Find and read the main entry file:
- `src/index.*`, `src/main.*`, `src/app.*`, `src/server.*`
- `main.py`, `app.py`, `manage.py`
- `Main.java`, `Application.java`
- `cmd/main.go`

### Step 5: Key source files
Read representative files from each major folder:
- Route/controller files — understand the API surface
- Model/schema files — understand the data layer
- Middleware files — understand cross-cutting concerns
- Config files — understand runtime configuration

---

## Phase 2 — Analysis (Reason about what you read)

After reading, answer these questions internally before writing:

1. What does this project do? One sentence.
2. What is the primary technology stack? (language, framework, database, runtime)
3. What architecture pattern does it follow? (MVC, layered, hexagonal, microservice, etc.)
4. What is the main entry point and request/execution flow?
5. Which files are most important for a new developer to understand first?
6. What environment variables are required and what do they control?
7. What commands does a developer need to run the project locally?
8. What are the external dependencies and what does each one do?
9. What is a realistic, scoped first task for a new developer?
10. What is the recommended order to read the codebase?

Use the stack detection table in `analysis-checklist.md` to confirm your stack identification.

---

## Phase 3 — Output (Write the report)

Use the structure defined in `report-template.md` to write the complete onboarding guide.

### Step 1: Write `docs/ONBOARDING.md`

Write the report to: `docs/ONBOARDING.md`

Rules for the output:
- Use the exact section headings from the template (they are parsed by the web viewer)
- Be specific — use actual file names, real command names, real dependency names from the project
- Keep each section concise but complete — a new developer should understand it without needing to ask follow-up questions
- For the "Recommended Learning Order" section, list actual files in the order they should be read
- For "Suggested First Task", make it realistic and scoped to 1–2 days of work
- End with the standard footer: `---\n_Generated by [DevOnboard](https://github.com/your-org/DevOnboard) · Powered by [IBM Bob](https://www.ibm.com/bob)_`

### Step 2: Update the embedded report in `viewer/index.html`

After writing `docs/ONBOARDING.md`, you MUST also update the embedded copy inside
`viewer/index.html` so the viewer works when opened as a local `file://` URL on Windows
(browsers block `fetch()` for local files — the embedded string is the only reliable path).

**How to update:**

1. Read the full content of the `docs/ONBOARDING.md` you just wrote.
2. Convert it to a JSON string using these exact escaping rules:
   - Replace every `\` with `\\`
   - Replace every `"` with `\"`
   - Replace every newline with `\n`
   - Replace every tab with `\t`
   - Keep all Unicode characters as `\uXXXX` escape sequences for any non-ASCII character
     (emoji, arrows, checkmarks, etc.) — this ensures the string is safe in all browsers
3. In `viewer/index.html`, find the block between the two marker comments:
   ```
   // EMBEDDED_REPORT_START
   var EMBEDDED_REPORT = "...";
   // EMBEDDED_REPORT_END
   ```
4. Replace the entire `var EMBEDDED_REPORT = "...";` line (only that line, not the markers)
   with the new JSON string value:
   ```
   var EMBEDDED_REPORT = "<your escaped content here>";
   ```
5. Leave the `// EMBEDDED_REPORT_START` and `// EMBEDDED_REPORT_END` marker comments
   exactly as they are — they are used by this step to locate the block.

**Important:** The viewer file uses only vanilla JS with no template literals anywhere near
the embedded string. Do not introduce backticks or `${` sequences into the replacement line.
