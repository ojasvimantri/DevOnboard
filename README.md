# DevOnboard

**Understand any codebase faster.**

DevOnboard uses IBM Bob as its core intelligence to analyze an unfamiliar project and produce a structured, navigable onboarding guide — automatically.

---

## Problem

Being handed an unfamiliar codebase without context is one of the most common pain points in software development. A new developer typically has to:

- Trace entry points and request flows across many files
- Identify the technology stack, runtime, and framework versions
- Locate environment variables, migration steps, and startup commands
- Understand the architecture pattern before writing a single line

This investigation is repetitive, time-consuming, and often undocumented. DevOnboard eliminates it.

---

## Solution

DevOnboard integrates directly into IBM Bob. A developer opens any project, activates the **🧭 New Dev Onboarding** mode, and runs a single command: `/onboard`.

Bob reads the codebase, reasons about what it finds, and writes a complete 10-section guide to `docs/ONBOARDING.md`. The included viewer presents that guide as a polished, navigable interface — no server or Node.js required.

The generated guide covers:

1. **Project Overview** — What it does and who it is for
2. **Technology Stack** — Full table with versions
3. **How to Run** — Step-by-step setup commands
4. **Important Files & Folders** — Annotated file tree
5. **Architecture** — Pattern explanation and request flow
6. **Dependencies** — Every package with its purpose
7. **Configuration & Environment Variables** — Full variable reference
8. **Development Commands** — Ready-to-use command reference
9. **Recommended Learning Order** — Actual files in read order
10. **Suggested First Task** — A scoped, realistic first contribution

---

## How IBM Bob Powers DevOnboard

IBM Bob is the intelligence engine of DevOnboard, not a tool used to build it. The entire analysis-and-generation pipeline runs inside Bob at runtime:

```
1. Developer opens an unfamiliar project in IBM Bob
        ↓
2. Switches to the "🧭 New Dev Onboarding" custom mode
        ↓
3. Types /onboard — a single slash command triggers the full pipeline
        ↓
4. Bob activates the onboarding skill and enters Phase 1: Discovery
   → reads README, package files, env templates, entry points,
     routes, controllers, models, middleware, and config files
        ↓
5. Phase 2: Analysis
   → reasons about the stack, architecture, critical files,
     environment dependencies, and a realistic first task
        ↓
6. Phase 3: Output
   → writes docs/ONBOARDING.md using the 10-section template
   → updates the embedded report inside viewer/index.html
        ↓
7. Developer opens viewer/index.html — polished guide, no server needed
```

Bob features used:

| Feature | Role in DevOnboard |
|---|---|
| **Custom Mode** (`new-dev`) | Scoped persona: read-only except Markdown; staff-engineer role |
| **Skill** (`onboarding`) | 3-phase workflow: Discovery → Analysis → Output |
| **Slash Command** (`/onboard`) | Single trigger for the entire pipeline |
| **Rules** (`onboarding-rules.md`) | Enforces report structure, source-code safety, and output path |
| **AGENTS.md** | Persistent project context available to every Bob session |

## Demo

### Requirements

- [IBM Bob IDE](https://www.ibm.com/bob) installed
- No other tools required

### Steps

1. Clone the repository and open the `DevOnboard/` folder in IBM Bob
2. Bob detects `.bob/` and loads the custom mode automatically
3. Click the mode selector and choose **🧭 New Dev Onboarding**
4. In the chat, type `/onboard` and press Enter
5. Bob reads `sample-project/`, analyzes it, and writes `docs/ONBOARDING.md`
6. Open `viewer/index.html` directly in any browser — the report loads immediately

> The viewer works as a local `file://` — no server, no `npx`, no Node.js required.
> The current report for `sample-project/` is already included in `docs/ONBOARDING.md`
> and embedded in the viewer, so the guide is visible before running `/onboard`.

---

## Key Features

- **Zero runtime dependencies** — the viewer is a single self-contained HTML file
- **Bob-native** — built entirely from Bob modes, skills, slash commands, and rules; no external code
- **Read-only mode** — Bob cannot modify source files; it only reads and writes Markdown
- **Deterministic output** — every report follows the same 10-section template parsed by the viewer
- **Multi-language** — the skill detects Node.js, Python, Java, Go, Rust, Ruby, and PHP projects
- **Self-updating viewer** — each `/onboard` run re-embeds the latest report in the viewer

## Setup

1. Install [IBM Bob IDE](https://www.ibm.com/bob)
2. Clone this repository: `git clone https://github.com/your-org/DevOnboard.git`
3. Open the `DevOnboard/` folder in Bob (`File → Open Folder`)
4. Bob loads the `.bob/` configuration automatically — no install step needed

To view the pre-generated report without running `/onboard`:

- Open `viewer/index.html` in any browser directly from the file system

To generate a fresh report against `sample-project/`:

- Switch to **🧭 New Dev Onboarding** mode and run `/onboard`

To use DevOnboard on your own project:

- Copy the `.bob/` folder into your project root, open it in Bob, and run `/onboard`

## Why It Matters

Onboarding documentation is frequently out of date, incomplete, or nonexistent. DevOnboard generates it on demand, directly from the actual codebase state. The output is scoped to what a developer needs on day one: where to start, what to run, what each file does, and a concrete first task. Because it runs inside Bob, it benefits from the same codebase-reading depth that a senior engineer would apply manually — applied consistently, every time.
