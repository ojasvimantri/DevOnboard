# DevOnboard — Onboarding Mode Rules

These rules apply automatically whenever the `new-dev` (🧭 New Dev Onboarding) mode is active.

## Core Rules

1. **Always activate the onboarding skill first.**
   Before doing any analysis, activate the `onboarding` skill.
   Do not start reading files until the skill is loaded.

2. **Read before writing.**
   Complete Phase 1 (Discovery) and Phase 2 (Analysis) fully before writing any output.
   Never write a partial or incomplete report.

3. **Source code is read-only.**
   You may only write to Markdown (`.md`) files.
   Never modify `.js`, `.ts`, `.py`, `.json`, `.yaml`, `.env` or any source file.

4. **The report goes to `docs/ONBOARDING.md`.**
   Always write the final report to this exact path.
   If `docs/` does not exist, create it first.

5. **Use real values — never generic placeholders.**
   Every section must reference actual file names, commands, variable names, and package names
   found in the codebase. Do not write generic advice.

6. **Missing information is stated explicitly.**
   If a section cannot be determined from the codebase (e.g., no README, no .env.example),
   write: `> Not found — check with the project team.`
   Never invent or assume values.

7. **Keep the 10-section structure intact.**
   The web viewer parses the section headings. Do not rename, reorder, or remove sections.

8. **End with the footer.**
   The last line of every report must be:
   `_Generated by [DevOnboard](https://github.com/your-org/DevOnboard) · Powered by [IBM Bob](https://www.ibm.com/bob)_`
