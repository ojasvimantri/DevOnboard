How IBM Bob Powers DevOnboard
The analysis pipeline runs entirely inside IBM Bob — no backend, no API, no cloud service.
1
Open project in IBM Bob
Open the DevOnboard workspace (or any project) in IBM Bob IDE. The .bob/ configuration folder is detected automatically.
2
Switch to New Dev Onboarding mode
Activate the 🧭 New Dev Onboarding custom mode. Bob’s persona becomes a staff engineer focused on codebase analysis. Source files become read-only.
3
Run /onboard
The slash command activates the onboarding skill and starts the 3-phase workflow: Discovery → Analysis → Output.
4
Bob reads and analyzes the codebase
Bob reads READMEs, package files, entry points, routes, controllers, models, middleware, and config. It identifies the stack, architecture pattern, critical files, and a suitable first task.
5
Bob writes docs/ONBOARDING.md
A complete 10-section guide is written to your project. Bob also updates the embedded report inside this viewer so it opens correctly without any server.
6
Open viewer/index.html
Double-click in Windows Explorer. No server, no Node.js, no npm required. The guide loads immediately from the embedded content.
Bob configuration files
.bob/custom_modes.yaml — New Dev mode and read-only permissions
.bob/skills/onboarding/SKILL.md — 3-phase analysis workflow
.bob/commands/onboard.md — the /onboard slash command
.bob/rules/onboarding-rules.md — always-on safety and output rules
